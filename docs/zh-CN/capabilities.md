# 能力与边界

**面向一个可信本地用户，保留“实际读到了什么”的证据。** MCP 层把本项目能力提供给 Agent；它不是厂商提供的 MCP 服务，也不是凭据保险库。

## 数据来源

| 来源 | 接入路径 | 关键边界 |
|---|---|---|
| WHOOP | 官方 OAuth 与文档化 API | 需要自己的合规应用配置及用户授权；摘要不是原始传感器波形。 |
| Garmin | 非官方个人 Garmin Connect | 首版只实现国际区账号，不支持中国区；与官方开发者计划分开，上游协议变化会影响接入。 |
| 合成数据 | 本地测试样例 | 用于入门与回归测试；不能证明真实健康状况或真实连接成功。 |

Provider 库可脱离 MCP 单独使用。入口默认运行合成模式。真实读取必须显式开启并完成本地授权；MCP 工具不接收密码或令牌。

## 覆盖范围也是结果的一部分

- 区分服务商测量时间、记录更新时间与本次读取时间。
- Garmin 心率是已同步的离散样本。保留有效点数、时间范围和缺测，不补造连续覆盖。
- 活动分页有界：每页 20 条，最多 10 次活动请求、扫描 200 条、30 秒活动请求预算；重试也计入请求数。触及限制可能漏项。
- `api_pagination_exhausted` 只表示上游日期查询已翻到空页；设备同步仍为 `unknown`，列表快照一致性仍为 `not_guaranteed`。
- 重复页、无进展、失败及限额必须体现在状态/原因中；空结果不能证明没有运动。
- WHOOP 当前读取滚动七天；Garmin 默认为配置时区的昨日，只有真实 Garmin 读取接受 `--day`。比较来源前先看实际记录日期。
- 明确配置日期日界，不根据 IP 或设备显示时差推断账号时区。

## 从记录到报告

CLI/MCP 输出来源数据和已观察心率样本的描述统计。接入的 Agent 根据问题撰写解读与报告，仍须遵守用户授权及服务商条款。模型能分析所提供的历史，不等于会长期保存它。长期档案、保留策略、跨设备核对和定时报告需要另行建设，不会因克隆工具包而自动启用。

## 首版明确不覆盖

不提供公开多用户托管、厂商背书的 MCP、连续原始心率波形、逐分钟睡眠阶段保证、设备同步完整性保证、诊断或内置定时送达。远程 Agent 平台仍需运行时适配及可靠的身份、秘密存储边界；复制本地配置不能自动获得这些能力。

实际验证级别见[验收说明](../validation.md)，有依据的报告方式见[分析指南](analysis-guide.md)。
