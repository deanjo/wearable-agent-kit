# 排障：修复真正失败的那一层

**先确定失败阶段，再决定是否重试。** 配置、授权、取数、持久化、报告和送达是不同阶段。真实读取失败时不能用合成数据替代。

| 现象 | 最小安全处理 | 必须取得的证据 |
|---|---|---|
| 登录成功，但没有预期设备或数据 | 显式核对账号与中国区/国际区。购买地和当前位置不能确定数据区域；不要跨区反复试密码。 | 所选账号出现预期设备或已知近期记录。 |
| 登录表单在到达服务商前被拒绝 | 浏览器部署应检查自身 Origin/CSRF 策略。页面采用 `no-referrer` 时，原生表单可能发送 `Origin: null`。采用合适的同源 Referrer 策略，不通过放行任意/null Origin 解决。 | 同源请求成功，跨源/null Origin 攻击仍失败。默认 stdio 不涉及该问题。 |
| WHOOP 已同意授权，回调仍失败 | 核对注册的精确回调地址、state、重复关键参数及文档允许的额外查询字段。不因无害的已知额外参数拒绝整个回调。 | 一次性 state 匹配，回调成功，日志没有授权码。 |
| 令牌请求重定向，或运行时拒绝重定向模式 | 将 3xx 单独处理，核对端点与运行时行为，不把凭据转发至不可信重定向目标。 | 重定向测试安全失败，规范端点成功。 |
| 刷新一度成功，随后连接失效 | 防止并发刷新；重试前核对已保存的令牌版本。写入或传输结果不明时进入阻塞状态，不重放旧令牌。 | 锁与故障注入测试通过；新进程能读到已提交版本。 |
| 更新后工具仍显示旧能力 | 检查可执行文件路径、版本、客户端/工具目录缓存及实际返回结构；按需重启或刷新客户端。 | 预期版本、成功调用和当前覆盖字段；“已连接”不足以证明取数成功。 |
| 活动少了，或返回空列表 | 检查分页状态、原因及覆盖字段。限额、重复页、无进展、错误或设备未同步均可能漏项。 | 分别说明查询是否翻完、设备同步是否已知、快照是否一致。 |
| “今天”的结果其实是旧测量 | 对比测量日期、更新时间、读取时间和配置的时区。 | 按来源标明实际记录时间；旧记录不冒充今日记录。 |
| 定时报告迟到或没来 | 在实际调度器中分别检查计划时间、触发、执行和发送状态。 | 发送被接受不等于已读；配置成功不等于任务执行。本项目不提供调度器。 |

## 排障时保护数据

只收集版本、服务商、配置的区域/时区、固定错误码、分页状态和合成复现。不要附上秘密、健康记录、完整回调地址、原始请求头或服务商响应正文。提交 Issue 前优先用测试样例复现。

## 真实接入仍需单独验收

假传输层测试通过，只能验证代码路径，不能证明账号可用、当前协议兼容、生产存储可靠或长期刷新稳定。按[验收说明](../validation.md)取得证据后，才能宣称真实接入成功。Garmin 个人 Connect 路径非官方，可随时变化；不得绕过安全检查或限流。
