# 把记录变成有依据的分析

**先给证据支持的结论，再解释不确定性和下一步需要观察什么。** 本项目用于数据质量检查和非诊疗趋势探索，不提供临床判断或专业建议。

## 1. 先确定观察窗口

区分测量时间、服务更新时间和读取时间。采用配置的账号日期日界，不因旅行或网络地址擅自改变。午睡与主睡眠分别标记；恢复记录与睡眠或周期匹配前，不认定其对应某晚。

## 2. 先检查覆盖，再计算

报告有效心率点数及首末测量时间。它们是已同步的离散样本，不是连续原始波形；缺测不补零。活动查询翻到空页，不代表设备记录全部同步；受限或失败的扫描可能漏项。不能据此计算完整全天训练总量。

## 3. 使用可比数据

同一指标优先比较同来源、同定义、同时间窗口及个人已有历史。短期历史不等于稳定基线。保留单位与来源标签。WHOOP 与 Garmin 可能记录同一运动，匹配确认前分别列出，不相加。

## 4. 解释变化，不编造原因

可靠的表述包含观察、比较、限制和下一步。以下完全为合成案例：

> 已有白天心率样本覆盖 09:10–17:20，其中位数高于上一个有记录日；但两日覆盖不同，也缺少运动时间信息。应先比较相同时间窗口，再判断趋势。

不要只凭分数说“恢复很好”，凭空列表说“当天没运动”，或因只在白天佩戴的手表没有夜间数据就说“睡眠差”。不推断诊断，不开治疗方案，不用免责声明包装医疗建议。

## 建议报告顺序

1. 数据是否可用、是否新鲜。
2. 主睡眠及已匹配恢复记录，如有。
3. 静息心率、HRV 及同来源历史，如有。
4. 白天心率覆盖与分别注明来源的活动。
5. 有依据的变化、不确定性及值得补充的观察。

用途限制参见 [WHOOP API 条款](https://developer.whoop.com/api-terms-of-use/) 与 [安全说明](../../SECURITY.md)。部署前审查具体用途；技术上能访问不等于任何分析都获准。
